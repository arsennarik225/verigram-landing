# Verigram — готовый лендинг

Статический сайт из присланного dev-kit с адаптацией под desktop и mobile. Четыре аудиозаписи и описания заменены на актуальные. Сервер, Node.js и сборка для публикации не нужны.

## Опубликовать на GitHub Pages

1. Распакуй архив `verigram-landing-ready.zip`.
2. В GitHub нажми **+ → New repository**. Название: `verigram-landing`. Выбери **Public**, затем **Create repository**. Если компания дала свой репозиторий, используй его.
3. Нажми **uploading an existing file** (или **Add file → Upload files**).
4. Перетащи содержимое распакованной папки: `index.html`, `styles.css`, `app.js`, папку `assets` и остальные файлы. Загружай содержимое, а не ZIP и не внешнюю папку. `index.html` должен оказаться в корне репозитория. Нажми **Commit changes**.
5. Открой **Settings → Pages**. В **Source** выбери **Deploy from a branch**, ветку **main**, папку **/(root)** и нажми **Save**.
6. Дождись успешного развёртывания. На этой же странице появится ссылка вида `https://USERNAME.github.io/verigram-landing/`. Открой её с телефона и проверь все четыре записи.
7. Отправь ответственному за домен ссылку на сайт и название GitHub-аккаунта. Дай ему доступ к репозиторию, если он будет настраивать Pages сам.

Публичный репозиторий делает исходники и аудиофайлы доступными всем. Если компания использует закрытый репозиторий, доступность Pages зависит от её тарифа GitHub.

## Подключить домен

1. Получи от команды точный адрес, например `voice.verigram.kz`. Это только пример, домен в проекте не задан.
2. Сначала в **Settings → Pages → Custom domain** введи этот адрес без `https://` и сохрани.
3. Для поддомена администратор DNS создаёт запись **CNAME**: имя `voice` (для примера выше), значение `USERNAME.github.io` — без `https://` и без `/verigram-landing/`.
4. Дождись успешной проверки DNS и выпуска сертификата, затем включи **Enforce HTTPS**, когда опция станет доступна. Обновление DNS может занять до 24 часов.
5. Если используется основной домен, а не поддомен, администратор должен настроить A/ALIAS/ANAME по документации GitHub ниже.
6. Проверь конечный HTTPS-адрес в приватном окне и на телефоне через мобильный интернет.

## QR

После подключения домена передай дизайнеру конечную HTTPS-ссылку. QR должен вести на неё. Для перехода прямо к записям добавь `/#audio` к домену. До печати проверь сканирование QR камерой телефона. Сам QR не создавался, потому что конечный адрес ещё не предоставлен.

## Файлы и правки

- `index.html` — тексты, карточки, контакты и ссылки кнопок.
- `styles.css` — оформление и мобильная адаптация.
- `app.js` — воспроизведение, пауза, перемотка, фильтры языка; одновременно играет только одна запись.
- `assets/audio` — четыре актуальные записи в MP3 и их описания с длительностями.
- Все пути относительные: работают и в подпапке GitHub Pages, и на отдельном домене.
- Кнопки внизу открывают почту; контакты сохранены из dev-kit.
- Шрифт Onest подключён через Google Fonts, при недоступности используется системный шрифт.
